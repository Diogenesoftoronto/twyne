### `computePopoverGeometry(view: PopoverView): PopoverGeometry` (lines 107–147)
**Yes — this is exactly the flip/clamp logic you want.** Documented rules at lines 94–106:
1. Prefer below (`rect.bottom + margin`).
2. Flip above **only** when `spaceBelow &lt; idealH &amp;&amp; spaceAbove &gt; spaceBelow`. Ties fall through to below.
3. Clamp `maxH` to the winning side's space, so the card never overlaps the anchor.

```ts
const x = Math.max(margin, Math.min(view.rect.left, view.vw - POPOVER_CARD_WIDTH - margin));
const belowTop = view.rect.bottom + margin;
const aboveBottomCoord = view.rect.top - margin;
const spaceBelow = Math.max(0, view.vh - margin - belowTop);
const spaceAbove = Math.max(0, aboveBottomCoord - margin);
const flipAbove = spaceBelow &lt; idealH &amp;&amp; spaceAbove &gt; spaceBelow;

if (flipAbove) {
  const maxH = Math.max(0, Math.min(idealH, spaceAbove));
  return { x, top: null, bottom: Math.max(0, view.vh - view.rect.top + margin), maxH, placement: "above" };
}
const maxH = Math.max(0, Math.min(idealH, spaceBelow));
return { x, top: belowTop, bottom: null, maxH, placement: "below" };
```
Deliberate design note (lines 100–103): the flipped card is **bottom-anchored** so it grows upward and doesn't jitter as content streams in. That reasoning applies to the slash menu too, where the list length changes as the query is typed.

**API limitation for your fix:** `POPOVER_CARD_WIDTH` is hard-coded inside the function. To reuse for a 288px menu you'd need to add an optional `width?: number` to `PopoverView` (defaulting to `POPOVER_CARD_WIDTH`) — a small, test-covered change.

### `computeMarginCardGeometry(view: MarginCardView)` (lines 64–92)
Right-margin-first, left-margin fallback, clamp-to-edge otherwise; always returns `placement: "below"` with a top clamped into `[margin, vh - maxH - margin]`. This is the one `twyne-editor.tsx` actually imports (line 169), used at lines 1126, 2042, 2381.

## 2b. The three drag systems, layered on one another

### (i) Qwik `preventdefault:` on the scroll container — the biggest suspect

`/home/diogenes/Projects/twyne/src/components/editor/manuscript-panel.tsx:42-51`, verbatim:

```tsx
      &lt;div
        class="flex-1 overflow-y-auto overflow-x-auto"
        style="background: var(--color-editor-bg);"
        preventdefault:dragover
        preventdefault:dragleave
        preventdefault:drop
        onDragOver$={props.onDragOver$}
        onDragLeave$={props.onDragLeave$}
        onDrop$={props.onDrop$}
      &gt;
```

This div is the **ancestor of the entire ProseMirror DOM** (`#twyne-editor-mount` is nested inside it at line 102).

**Critical mechanism:** Qwik registers its delegated listeners on the document in the **capture phase**, and calls `preventDefault()` *before* the event ever reaches ProseMirror. From `node_modules/@qwik.dev/core/dist/qwikloader.debug.js`:

```js
// line 379 — note the 4th arg `true` = capture
roots.forEach((root) =&gt; addEventListener(root, eventName, processElementEvent, true, passive));

// line ~28 — signature
var addEventListener = (el, eventName, handler, capture = false, passive = false) =&gt;
    el.addEventListener(eventName, handler, { capture, passive });

// line 150 — inside dispatch(), walking target → ancestors
if (allowPreventDefault &amp;&amp; element.hasAttribute("preventdefault:" + kebabName)) ev.preventDefault();
```

So on **every** `dragover`, `dragleave`, and `drop` anywhere inside the manuscript, `event.preventDefault()` fires at document-capture, ahead of `view.dom`'s handlers, ahead of Dropcursor, ahead of `SectionReorder.handleDOMEvents`, ahead of `editorProps.handleDrop`.

For `dragover` this is benign-to-helpful (it's how you mark a drop target). For **`drop` it cancels the browser's native drop default for the whole subtree** — and it's applied unconditionally to text-selection drags, file drags, everything.

**(b) Every drop near the top of the document resolves to the H1.** `section-reorder.ts:126` — `let target = outline.flat[0];` with no guard for "coordinates are above the first heading."

**(d) The drop cap interacts with H1 ordering** (`global.css:738-746`):

## 7. Documented gotchas — `docs/browser-models.md` is genuinely valuable

This doc is the single best artifact for your purposes. Its four hard requirements:

1. **ONNX in transformers.js layout.** *"GGUF, MLX, safetensors, and onnxruntime-genai layouts are all unloadable — the loader fetches paths that do not exist and fails as a 404."*
2. **4-bit or 8-bit only.** *"ONNX Runtime's `MatMulNBits` kernel accepts nothing else; sub-4-bit weights fail at session creation with `bits must be 4 or 8`. That string lives in the ORT WASM binary, so no loader-side dtype config works around it."* A q2 Gemma export *"Shipped briefly and failed in production."*
3. **Architecture transformers.js implements** (`lfm2`, `lfm2_moe`, `lfm2_vl`, `qwen3`, Gemma families). No `trust_remote_code`.
4. **Download ≈ VRAM footprint.**

Plus a "Queued" table (LFM2 1.2B at 0.76 GB is *"the smallest option found anywhere"*; Bonsai 1.7B q4 is *"the one entry that would run on a GPU **without** `shader-f16`"*) and a "Ruled out" section covering Maple Preview, Bonsai 27B, Gemma 12B.

Other gotchas:
- **WebGPU is mandatory** for the LLM. `classifyLocalModelError()` (line ~106) translates raw errors into guidance: *"requires Chrome 113+ or Edge 113+"*, `shader-f16` missing, OOM (*"Close other GPU-heavy tabs"*), 404, network.
- **COOP/COEP are set** — `web/vite.config.ts:647-648` and `web/nitro.config.ts:5-6`:
  ```
  "Cross-Origin-Opener-Policy": "same-origin",
  "Cross-Origin-Embedder-Policy": "credentialless",
  ```
  Note `credentialless` rather than `require-corp`, plus `Cross-Origin-Resource-Policy: cross-origin` in dev. These appear to be there for the nodepod SharedArrayBuffer sandbox, but they also enable multithreaded ORT-WASM.
- **Download UX** is elaborate: `lib/model-download-progress.ts` (`DownloadTracker`, phases `checking → downloading → preparing → ready`), repaint throttled to ~7 fps (`PROGRESS_NOTIFY_INTERVAL_MS = 140`), and a `PREPARING_DELAY_MS = 1200` heuristic because *"Cached weights emit no progress events at all, so say 'preparing' rather than sitting at 0% for the whole load."* UI in `web/src/components/ModelDownloadBar.tsx` and `ModelSelector.tsx`.
- **No cache-eviction policy.** Manual delete only.
- LiteRT-LM's JS runtime is explicitly ruled out for browser: *"currently documents support only for the web-specific Gemma 4 E2B/E4B bundles; general `.litertlm` files are not yet supported."*

## 5. `src/utils/supertonic-tts.ts` (366 lines) — the caching precedent

This is exactly the precedent you suspected, and the pattern differs from Keating's in an important way.

Split across three files:
- **`src/utils/browser-inference.ts`** (4.6 KB, dependency-free) — capability detection + the manifest. Kept separate deliberately: *"`supertonic-tts.ts` pulls in the full transformers.js runtime, which is hundreds of kilobytes the main bundle must not carry."*
- **`src/utils/models-cache.ts`** — generic download/evict.
- **`src/utils/supertonic-tts.ts`** — the transformers.js layer.

**Model:** `onnx-community/Supertonic-TTS-ONNX`, ~262 MB across 9 model files + 9 voice embeddings (`BROWSER_TTS_MANIFEST`, `browser-inference.ts:44`). Biggest: `onnx/latent_denoiser.onnx_data` at 132,098,880 B.

**Device selection** — unlike Keating, WASM is a real fallback:

```ts
export function browserTtsDevice(): BrowserTtsDevice {
  if (capabilityOverride !== undefined) return capabilityOverride;
  if (typeof window === "undefined" || typeof navigator === "undefined") return null;
  if ("gpu" in navigator &amp;&amp; navigator.gpu) return "webgpu";
  if (typeof WebAssembly !== "undefined") return "wasm";
  return null;
}
```

**Caching = IndexedDB `models` store, keyed by remote URL**, with an `env.fetch` redirect — a genuinely different design from Keating's "let transformers.js use Cache Storage":

```ts
export function installSupertonicFetchHook(): void {
  if (fetchHookInstalled || typeof window === "undefined") return;
  fetchHookInstalled = true;
  const originalFetch = env.fetch.bind(env) as typeof fetch;
  env.fetch = async (input: string | URL, init?: RequestInit) =&gt; {
    const url = typeof input === "string" ? input : input.toString();
    if (url.startsWith(REMOTE_BASE)) {
      const bytes = await readModelBytes(url);
      if (bytes) {
        return new Response(bytes, { status: 200, headers: { "content-type": "application/octet-stream" } });
      }
    }
    return originalFetch(url, init);
  };
}
```

Doc comment: *"Once the pack is on disk, this hook answers those fetches from IndexedDB instead of the network, so a reading works with no connectivity at all."*

**The store** — `src/utils/idb.ts:106` `ensureStore("models", "id")`; record type at line 1197:

```ts
export interface ModelFileRecord { id: string; blob: Blob; bytes: number; updatedAt: number; }
```

with `saveModelFileToIdb` / `loadModelFileFromIdb` / `listModelFilesFromIdb(prefix)` / `deleteModelFileFromIdb` (lines 1205-1265). `listModelFilesFromIdb` does a full `getAll()` then filters by prefix — fine for ~18 files, worth noting if you add GB-scale LLM weights.

**`src/utils/models-cache.ts`** header states the intent outright:

&gt; *"The download-and-evict capability that both the Supertonic voice pack **and any future local model** share."*

`downloadModelBundle(id, manifest, {signal, onProgress})` fetches **sequentially** — *"so a browser's connection pool is never competing with the page's own traffic, and each file lands whole"* — with a proper `AbortSignal` and a listener registry (`onModelDownload(id, listener)`). `modelDownloadState()` derives `not-downloaded | downloading | ready | error` from bytes on disk without touching the network. `evictModelBundle` deletes by shared URL prefix.

Pipeline loading is memoized with a warm-up pass:

```ts
const tts = (await pipeline("text-to-speech", SUPERTONIC_MODEL_ID, { device, progress_callback: () =&gt; {} })) as TextToAudioPipeline;
// Warm up so the first real reading is not the one that pays for shader compilation.
await tts("Hello", { speaker_embeddings: new Float32Array(1 * 101 * 128), num_inference_steps: 1, speed: 1.0 });
```

Errors are structured `AppError`s with a `download-required` recovery action so the UI can point at the download rather than claiming the voice is broken.

**No Web Worker here either** — TTS runs on the main thread.

**There is no online/offline branch inside the AI paths.** I grepped `navigator.onLine` across `src/` — the only hit near AI is `src/components/desk/usage-sync-controller.tsx:60`. ## 7. Where a browser LLM would plug in — concretely

The seam is clean. `createModel()` at `ai-client.ts:264` returns `LanguageModel | null`; everything above it (`runOnce`, `generateTrackedText`, tools, tracing, usage) is provider-agnostic. Twyne already has `@huggingface/transformers` installed, a `models` IndexedDB store with download/evict/progress, and the managed-provider inject/strip pattern.

Four things to be aware of:

1. **You'd need to write an AI-SDK `LanguageModelV2` adapter** around transformers.js — Keating's approach (a bespoke `hybridStreamFn` branch bypassing the provider interface) won't transfer, because Twyne's `createModel` must hand back a real `LanguageModel`. Keating's `createBrowserStreamFn` is a useful reference for the *event shape*, not the *interface*.
2. **Tool calling is load-bearing** in Twyne (`quote_passage` anchors editorial notes) and Keating's browser path has none. The `eval:local` harness exists precisely to measure this.
3. **The `&lt;think&gt;` re-run bug** — `generateTrackedText` discards replies with reasoning tags, doubling cost on LFM2.5. The eval's `wouldRegenerate` metric says a per-provider "reasoning is expected" flag is needed before free mode ships.
4. **Two competing cache strategies now exist** — Keating uses transformers.js's native Cache Storage (`useBrowserCache = true`); Twyne uses IndexedDB blobs + an `env.fetch` redirect. Twyne's gives true offline + precise eviction; Keating's is less code. They conflict if both run in one app, since Twyne's fetch hook is installed globally on `env.fetch` and Keating-style loading would bypass it.</result>
