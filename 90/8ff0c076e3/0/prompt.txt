## The feature: Alternatives
A writer locks a span of the manuscript (selection toolbar "Alternatives" button, or Shift+F7; a bare caret locks the word under it) and browses replacements of about the same word count.
- Single word: the "drum". The option being looked at stands in for the word in the sentence (a ProseMirror widget decoration, the doc is not changed), with the previous/next option shown faded above/below the word. Up/Down, the mouse wheel over the word, or a vertical swipe on touch step through options; Left/Right jump between kinds (model picks "fits here", dictionary synonyms, slot fillers, antonyms). Word lists come from the Datamuse API in the browser; model picks stream in from the writer's own provider (BYOK) or Twyne's hosted model via a Convex action.
- Phrase/sentence/paragraph: a column in the page margin with a dashed leader line to the span, filter chips by kind, a "steer" input that asks the model for rewrites toward a direction the writer types, and a fallback "sheet" layout when there is no margin room.
- Enter applies the option as one undoable replacement (keeps marks), Escape restores the original and the selection, clicking elsewhere closes. Every candidate is held to the original's length window before it is shown.
- Animations: drum roll, sweep on lock, bump at the ends, applied text "ink" that dries, margin slide in/out with a delayed unmount, staggered options, gliding cursor bar. All motion is meant to be off under prefers-reduced-motion except the colour-only ink fade.

## What to look for, in priority order
1. Correctness bugs: races between async fetches and a lock that closed or was replaced; stale state after Escape/apply; ProseMirror position mapping of the lock and the applied-text flash through edits; the "locked words changed" auto-close; undo history pollution (previews must not enter history); apply when marks span the edge; keyboard handling conflicts with the editor's own shortcuts or IME composition; the delayed unmount ("leaving") letting input through or leaking timers; cache key collisions.
2. Security and spend on the hosted path (convex/alternatives.ts): auth, rate limiting, argument bounds (string lengths, array sizes, count), anything a caller can use to make the model do unbounded work, data leakage. Read convex/_generated/ai/guidelines.md first for this repo's Convex rules. Also check the Datamuse requests send only the word and its two neighbours.
3. Qwik pitfalls: closures captured into useVisibleTask$ vs QRLs, reading store state inside lazily loaded handlers, components rendering null with visible tasks, list keys, the repo's custom lint rules in packages/eslint-plugin-qwik-guards.
4. Accessibility: listbox/option roles and aria-activedescendant on both layouts, focus moving into the palette and back to the manuscript, screen-reader text for the drum.
5. Motion: anything that animates under prefers-reduced-motion that should not, layout thrash, animations that can stack or never finish, the width tween on the word preview.
6. CSS that breaks in dark themes or at phone width, z-index conflicts, print styles.
