## The architecture you asked for

You're right that this belongs in Not Organic, and the codebase agreed more than I expected — `convex/lib/notorganic.ts` already had `providerJsonRequest()`, the exact helper a `/judgement` route needs, and `providerIdentity.ts` already calls `/v1/wallet` and `/v1/billing/checkout` that way. So this wasn't a new pattern, just an unused one.

**Twyne side** (`convex/systemOne.ts`) now prefers Not Organic and falls back to a direct key only for local dev:

```
notOrganicEnabled()  →  POST /v1/judgement   (DPoP product assertion, capability judgement:evaluate)
TYPESAFE_API_KEY     →  direct TypeSafe       (developer machines only)
neither              →  { ok: false, error: "unconfigured" }
```

One decision worth flagging: **Not Organic wins even when both are configured.** A machine with both is mid-migration, and silently preferring the local key there ships a surface never exercised against the real boundary.

Modelled on Tavus, because Jev has the same shape problem: it isn't chat, so forcing it through `/v1/chat/completions` would mean inventing a prompt envelope and parsing text back out — the exact round trip the model exists to remove.

Per-customer inspection works through the real ledger: `store.reserve` → `markDispatched` → `markAccepted` → `settle`, billed on Jev's actual `usage.input_tokens`. Pricing lands neatly — $0.042/Mtok input with free output is exactly **0.042 microUSD per input token**, so a full rubric pass is ~59 microUSD.
