# Equation field keyboard ownership audit

Read-only audit, 2026-10-05. The proposed patch and tests are **unapplied and unexecuted**. Existing Source/native/runtime files were not edited. No Cargo, Devenv, native display, browser, server, network or provider was run for this audit.

Source has two different boundaries. Its equation NodeView rejects ordinary ProseMirror events from every form descendant, but Twyne's separate document/window listeners deliberately handle some shortcuts from form buttons. Treating the whole form as a shortcut-free region would change current Source behavior.

## Focused textarea findings

1. **Tab edits the native raw field instead of leaving it.** Source's textarea callback handles Enter/Escape only ([math-source-editor.ts:176–202](../../../../../src/components/editor/math/math-source-editor.ts)); its NodeView `stopEvent` also prevents ProseMirror indentation ([math.ts:202–203](../../../../../src/components/editor/extensions/math.ts)). Native Kit binds Tab/ShiftTab to Input `IndentInline`/`OutdentInline` (`vendor/gpui-base/src/input/base/state.rs:184–185`). The actual retained field has `TextareaMode`, `LayoutMode::PlainText`, and two/three rows; `is_indentable()` admits PlainText (`input/editor/indent.rs:58–62`). `apply_indent` then edits the rope/history (`:246–292`). This is a concrete native edit path, not a guessed missing binding. Source callback inspection establishes no custom Tab edit; fresh browser traversal remains a Parent proof boundary.

2. **Root's command-dispatch guard does not cover all rich action entry points.** `RichEditorView::dispatch` checks the math textarea focus (`view.rs:658–673`). Rich movement/extension/document-edge/SelectAll action listeners instead call selection methods directly (`:1572–1611`). `delete_word`/`delete_grapheme` set selection and prepare a history group before reaching dispatch (`:816–864`). Copy can publish the manuscript atom; Cut calls `execute` directly; Paste closes typing/composition groups and may begin clipboard transport before dispatch (`:891–958`). `Window::dispatch_action` delivers a typed action to the focused element independently of keymap matching (`vendor/gpui-pre/src/window.rs:2442–2454`), and unhandled action types bubble to ancestor handlers (`:6371–6452`). Thus explicitly dispatching these **rich action types** while the textarea owns focus can still alter manuscript selection/history/clipboard. This is a defensive action-boundary hole in the new guard, not evidence of another stock keyboard shortcut leak.

3. **Ordinary rich keybindings already exclude a mounted form.** `EDITOR_KEY_CONTEXT` includes `!TwyneMathSourceForm` (`view.rs:116`). Pinned GPUI's `Not` predicate checks the whole context stack (`vendor/gpui-pre/src/keymap/context.rs:261–306`), so correctly mounted textarea and buttons suppress those rich bindings. Kit Input owns ordinary movement, selection, clipboard and history types. The new non-mac CtrlShiftZ alias remains local to `TwyneMathSourceForm > Input`. No additional stock movement/clipboard/format chord leak was executed or established by this audit.

## Small proposed correction

[integration.patch](integration.patch) adds a capture boundary on the **existing form root**, conditional on the exact retained textarea FocusHandle being focused. It consumes the 35 existing rich action types before ancestor movement/clipboard/deletion handlers run. It also intercepts only Kit `IndentInline`/`OutdentInline` for that focused field and calls public `Window::focus_next`/`focus_prev` using current measured tab stops. It adds no layout wrapper, focus trap, keybinding catalogue, document traversal, field replacement, command/history mutation or renderer choice. Kit field Copy/Cut/Paste/Undo/Redo/movement/selection and Source-specific Enter/Escape actions keep their own types. Direct host `execute(UpdateMathSource)`/canonical commit is unaffected.

The patch also registers the new native tests as a child of the existing math host test module. Its actual retained room/open helpers are reused; no fake successful converter or renderer is added. The patch does **not** change Root's `dispatch` guard, Source button exceptions, form-wide Escape or app Save/navigation policy.

## Button exceptions which must stay explicit

- Source document-capture Mod-A exempts an actual textarea inside the manuscript, but deliberately selects/focuses the manuscript from a form **button** (`twyne-editor.tsx:1093–1124`). The NodeView `stopEvent` does not cancel this earlier document listener.
- Source `onGlobalKeydown` treats textarea/input/select as editing fields and skips catalogue commands there. Buttons are not editing fields: when Source Write is active/not pending and the event is unprevented, it dispatches `twyne:editor-shortcut` for matched `EDITOR_KEYBINDINGS` (`twyne-editor.tsx:1749–1788`, `utils/keybindings.ts:14–51`). This includes format, history, navigation, **Tab and ShiftTab**. Source's `runShortcut` forwards to the real registry (`twyne-editor.tsx:3549–3556`). This audit proves requested command routing, not the eventual document result or browser focus. Native button Tab currently follows Kit traversal; that cannot be labelled full-product Source parity.
- Source equation Escape cancellation is attached only to `input.addEventListener("keydown", keydown)` (`math-source-editor.ts:176–202`). The open NodeView's own keydown returns early (`math.ts:166–167`). A button Escape can reach the global handler, which clears other popovers/find/outline without closing the equation (`twyne-editor.tsx:1790–1798`). Native `DismissMathSource` is currently bound to the whole `TwyneMathSourceForm`, so it closes from buttons too. This difference is recorded, not silently changed.
- Source `stopEvent` protects bubbling events reaching ProseMirror's ordinary `initInput` path (`node_modules/prosemirror-view/src/input.ts:45–55,90–98`). It does not forbid direct editor commands, globally captured actions or the separate public PM `dispatchEvent` method. No blanket global-shortcut refusal is implied.
