# Optional tenth image: independent native-proof proposal

These are **separate unapplied patches**. The responsive mount rebase and its
freeze are unchanged. The original `dossier-image-lifecycle/native-proof`
driver, source pins and receipts are unchanged, including their historical
nine-image assertions. Parent owns adoption and execution.

Review/apply after the product mount:

1. `native-observation.patch`: only the existing `ui-tests` observation method
   in `src/app.rs`. Adds actual held preparation presence/transparency, exact
   group ImageId, logical dimensions/DPR, recording status and Window backend
   capability. It retains no new image/Entity Arc, refreshes nothing and cannot
   upload or evict a key. Existing real window/App qualification, bounded trace,
   surface guards and capture sequence remain intact.
2. `native-driver-adaptation.patch`: only the original native proof driver's
   admission/accounting predicates and affected assertions. No capture, XTEST,
   private environment, recovery-fault, observed bounds, frame-marker chain,
   retirement ordering or clean-quit mechanism changes.

The original exact nine-image condition becomes **nine ordinary preparations
plus the directly observed optional group**. Native all-eight-stamp navigation
and all nine ordinary atlas uploads remain mandatory. A default Noop font test
with only paper/group cannot pass this real native lane.

The adapted driver's default `--expect-multiply supported` requires actual
Window support, `Recorded` scene admission and the observed group's real atlas
presence. `--expect-multiply unsupported` checks real default/refusal behavior
and explicitly forbids a group atlas key. `any` reports observed support while
maintaining these same respective conditions; it is not support proof. All
ordinary native proof still runs in each lane. Broadsheet's observed transparent
preparation owns no group image and requires status `Transparent`.

At fixed palette/DPR, resize must replace **paper and optional group**, retain
the same eight stamp keys, and retire only the replaced IDs through the original
accepted→refresh→marker→deferred-drop sequence. Exact `presentBefore` is checked
against actual uploaded-ID snapshots, not every prepared ID. Unsupported groups
are tracked and retire with `presentBefore=false`; they are never mislabeled as
uploaded. Resize-back, Cancel, actual House route, theme changes and reopen keep
the same original owner/canonical/answer checks.

Scope remains DPR1, integral opaque X11/WGPU fixture geometry. An observed
recording/key is not GPU completion, presentation, driver-memory reclamation or
Source radial-gradient raster equivalence. Same-size real platform DPR changes,
device loss, transparency/fades, fractional grids, multiwindow behavior and
positive-z Source transient overlays need separate Parent acceptance. This
proposal does not manufacture them.

`native-adaptation-pins.json` pins current original app/driver inputs and their
proposed outputs. `native-adaptation-check-receipt.json` records strict in-memory
reconstruction, Python AST checks and `rtk proxy git apply --check` only. Rust is
unparsed/uncompiled. No driver/native process or synthetic predicate test was
executed by this lane. `driver_contract_tests.py` contains six authored synthetic
observation checks for Parent; their results cannot establish native proof.

Parent-only proposed execution, after review/application/build:

```sh
rtk proxy python3 desktop/gpui/fixtures/dossier-image-lifecycle/native-proof/check-native.py --binary /absolute/immutable/ui-tests-binary --expected-binary-sha256 REVIEWED_SHA --output /absolute/fresh/private-output --expect-multiply supported
```

No utilities, providers or dependencies are installed by this proposal. The
original helper-byte pin remains enforced by the driver. If Parent changes that
helper, it must review and explicitly repin it; source-input drift is not silently
accepted by this lane.
