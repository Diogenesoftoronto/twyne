# Dossier stacking audit

Frozen read-only source audit. No browser, native, Cargo, Devenv or test execution was performed for this audit; no runtime patch is proposed. `inventory.json` records declarations and context-qualified inferences, and `proof-cases.json` lists pending actual observations. File and excerpt hashes are in `input-pins.json`.

The native foxing canvas is the final **Dossier child**, not the final Window paint. It runs after ordinary Dossier content, before Kit root overlays, deferred draws and GPUI's prompt/drag/tooltip stage. Source foxing is an absolute `::after` with `z-index: auto`, opacity `0.7` and `mix-blend-mode: multiply`; it does not have a positive z-index. Positive descendant z-index alone does not determine whether Source foxing is above that descendant.

## Source contexts

The declared TSX tree is `main.paper-sheet.paper-foxed` → overlays, capped wrapper → frame → chrome, two leaves, optional filed confirmation. The main and frame clip overflow. `props.overlays` is outside the frame and precedes its wrapper. This is a source-declared tree, not a new observed browser DOM. [dossier-folio.tsx](../../../../../src/components/onboarding/dossier-folio.tsx#L47), [global.css](../../../../../src/global.css#L3576).

The frame normally holds `dossier-file-settle` with `fill-mode: both` while filed. Its final value is `translateY(0) scale(1)`, which remains a non-`none` transform. I infer that it retains an atomic parent stacking context at stack level zero: the confirmation's `z-index: 10` is local to that context. Subject to the audited tree and absence of an additional ancestor context, the later auto-level foxing pseudo-element can multiply the whole frame, including its confirmation. This is a CSS ordering inference, not measured pixels. [global.css:5882](../../../../../src/global.css#L5882), [global.css:5890](../../../../../src/global.css#L5890), [global.css:5943](../../../../../src/global.css#L5943).

Reduced motion disables the frame's filed animation and transitions. It removes the animation-derived parent transform in the filed state; the confirmation's positive stack level can then participate in the surrounding context and paint above auto-level foxing. It **does not** reset the separate `filing` state's declared `scale(0.998)`, or the confirmation paper's static `rotate(-1deg)`. These distinctions require separate actual observations. [global.css:5873](../../../../../src/global.css#L5873), [global.css:5902](../../../../../src/global.css#L5902), [global.css:6079](../../../../../src/global.css#L6079).

The right leaf independently holds `folio-feed` for 260 ms with `both`; its final `translateY(0)` retains a transform context under ordinary motion. Reduced motion removes that animation. The confirmation paper also has its own transform/filter animation inside the confirmation; this does not let it escape a transformed frame. [global.css:5851](../../../../../src/global.css#L5851), [global.css:5961](../../../../../src/global.css#L5961).

For the form surface, Sending and submission-error overlays are fixed, explicitly `z-index: 60`, and outside the frame. They are not confined by the frame's filing transform. Recovery error is instead an unpositioned `.error-slip`; no z-index is specified there. The conversational call does not pass the form's `overlays` prop. These are different contexts, not one universal Dossier overlay order. [anti-tabula-rasa.tsx:715](../../../../../src/components/onboarding/anti-tabula-rasa.tsx#L715), [conversational-interview.tsx:592](../../../../../src/components/onboarding/conversational-interview.tsx#L592), [global.css:2430](../../../../../src/global.css#L2430).

Source also declares root view-transition snapshot animations (120/220 ms, opacity and translation), disabled for reduced motion. This audit does not establish that a particular departure activates a view transition, or that live-main paint order describes its separate snapshot presentation. Browser UA menus/top-layer UI are likewise outside the audited ordinary subtree. [global.css:90](../../../../../src/global.css#L90).

## Native order and concrete differences

Current `DossierView::render` mounts its prepared paper background first, the capped live frame next and the foxing canvas last. The canvas validates its window/image lease, actual palette, bounds and DPR; it paints only within the current mask. The multiply API gives the sprite a distinct overlapping paint layer. This establishes a local draw-order boundary, not a final window pass or general CSS stacking implementation. [dossier_view.rs:544](../../../src/dossier_view.rs#L544), [dossier_view.rs:2673](../../../src/dossier_view.rs#L2673), [window.rs:4976](../../../vendor/gpui-pre/src/window.rs#L4976).

The actual application initializes Kit's component layer and uses `gpui_kit::open_window`, which wraps application content in Base Root. Component initialization registers `WindowState` as a Root plugin. Base Root appends plugin views after application content; `WindowState` mounts sheet/dialog/notification layers, touch-selection, tooltip and native-menu overlays. They are mounted infrastructure, not proof of a currently visible popup. The exact cached 0.7.0 code is pinned in `input-pins.json`; no registry files were modified. [main.rs:489](../../../src/main.rs#L489), [main.rs:519](../../../src/main.rs#L519), [root.rs:280](../../../vendor/gpui-base/src/root.rs#L280).

GPUI then paints deferred draws by ascending priority (larger values later), followed by one of prompt, active drag, or core tooltip, in that precedence order. Debug inspector paint has additional stages. Base popups use priority 100, Base tooltip overlays 200, and Base dialogs `10 + layer`. These numbers compare deferred elements only; they do not map to Source CSS z-index. The component tooltip overlay and GPUI's core tooltip are separate mechanisms. [window.rs:3538](../../../vendor/gpui-pre/src/window.rs#L3538), [window.rs:3757](../../../vendor/gpui-pre/src/window.rs#L3757), [popup.rs:189](../../../vendor/gpui-base/src/popup.rs#L189), [tooltip.rs:221](../../../vendor/gpui-base/src/tooltip.rs#L221), [dialog.rs:548](../../../vendor/gpui-base/src/dialog.rs#L548).

There is also a concrete transient-state gap: native `Filed` rendering adds an ordinary in-flow status child rather than Source's absolute wash/confirmation paper. The successful application callback acknowledges filing and immediately removes the view; Source create/refine retain filed feedback for 780 ms. A standalone view that holds `Filed` is not evidence that the application displays Source's confirmation interval. [dossier_view.rs:2629](../../../src/dossier_view.rs#L2629), [app.rs:2130](../../../src/app.rs#L2130), [dossier-filing.ts:4](../../../../../src/utils/dossier-filing.ts#L4), [create/index.tsx:214](../../../../../src/routes/dossier/create/index.tsx#L214), [refine/index.tsx:137](../../../../../src/routes/dossier/refine/index.tsx#L137).

## Proof boundary

The retained `parent-native-pixel-gates.json` is an actual single-window, authored WGPU multiply probe (4,464 sampled pixels, zero mismatches under its one-byte tolerance). It does not prove Source's filed/reduced-motion stacking, product popup overlap, or a universal final-window multiply pass. This audit does not rerun or reinterpret it as those claims. See `proof-cases.json` for the remaining state/overlay observations and explicit limitations.

No change is proposed to painting, filing, animation, popups, fonts, or lifecycle. A future comparison must record actual state, motion preference, surface, ancestor transforms/isolation, timing, theme, viewport/DPR and which overlay is visible before deciding whether the native final-child treatment matches that case.
