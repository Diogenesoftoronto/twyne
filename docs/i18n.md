# Twyne interface languages

English is the source and fallback language. French, Spanish, Simplified Chinese, Hindi and Japanese are available. In automatic mode Twyne resolves the browser's ordered language preferences, including regional variants such as `fr-CA`. A choice in Settings overrides detection. The web app uses browser preferences as the proxy for OS language; it cannot read OS settings independently.

The language control belongs in Settings only. Automatic, English, Français, Español, 简体中文, हिन्दी and 日本語 are the available choices. Keep the stored preference separate from the resolved language so automatic detection continues to work when browser preferences change.

## Catalog workflow

Source copy lives in `src/i18n/messages/en.json`; translations live in the corresponding `fr`, `es`, `zh`, `hi` and `ja` JSON files. The initial nine messages per language were authored locally, not generated by a GT API call. This first slice covers the language settings and selected settings headings, not the whole application. Remaining English surfaces need migration to dictionary IDs and translations in each supported language.

The installed GT CLI does not detect a Qwik adapter as an inline framework. Use its supported JSON-file workflow from `gt.config.json`, then compile the translated JSON to canonical GT ICU hashes:

```sh
bun run i18n:check
# Once GT_PROJECT_ID and GT_API_KEY are configured for the CLI:
bun run i18n:translate
bun run i18n:compile
```

`i18n:check` is a dry run; it must find `src/i18n/messages/en.json`. It sends no files to GT. Translation calls require a configured project and may incur charges. Keep credentials in the shell or local environment configuration, never in the frontend or tracked files.

Commit source, translated JSON and the compiled `src/i18n/catalogs/*.json` together. Build-time compilation prevents runtime network dependence. The English source is retained for missing translations.

## Package and release boundaries

The standalone adapter lives under `packages/gt-qwik`, with its own manifest, build, tests and documentation. Twyne consumes it as a local workspace dependency through package exports. Publication is deferred. Run `bun run i18n:prepare` after a fresh install before standalone typechecks or development entry points; client/server build and `dev.frontend` scripts prepare it automatically. `bunfig.toml` retains Twyne's existing hoisted dependency layout.

As checked on September 21, 2026, npm's unscoped `gt-qwik` is already a General Translation placeholder at version 0.0.0. Publication requires coordination with that owner or a different package name. The current npm authentication check returns 401. Local implementation and package validation do not establish registry publication.

## Model replies

The same Settings preference controls model replies. Browser/BYOK and local model calls resolve it at request time; hosted actions receive a validated, optional `responseLocale` per request. Older callers default to English. Automatic uses the same ordered browser preference policy as the UI. Generic Chinese and regional `zh-*` preferences currently use the Simplified Chinese catalog.

The shared prompt policy asks for user-facing explanations, questions, feedback and summaries in the chosen language. Explicit user requests for another language take precedence. Verbatim quotations, citations, code, protocol markers, JSON keys and enum values stay unchanged. Transcription preserves the spoken language; manuscript replacements preserve the manuscript language unless translation is requested. Existing messages are not retroactively translated. Static fallback/error copy is still part of the broader untranslated UI backlog.

Tests verify request instructions, not actual provider fluency. Deploy the updated hosted action validators before deploying a frontend that sends `responseLocale`; an older backend rejects unknown arguments. This change has not been deployed.
