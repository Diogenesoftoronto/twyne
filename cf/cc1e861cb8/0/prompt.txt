## Task 1 — flow sessions (the "galley slip")

When the page enters `flow` mode, open a session; when it leaves flow (to any
other mode), when the writer releases focus (Escape / reaching / manual zen
off), or when the conductor stops (editor destroyed / folio change), close it.
Build a `FlowSession` (see `src/utils/flow-session.ts`):

- `flowMs`: time from entering flow to leaving it.
- `words`: net words added during the session (the conductor already tracks
  inserted/deleted chars per transaction; count words with the same 5.5
  chars/word used by `wordsSinceDrift`, or better, diff the doc's word count
  at start vs end — choose the more honest one, never negative).
- `wpm`: words / minutes, rounded.
- `waited`: how many distinct items were upserted or held while the session
  was open (i.e. what the quiet page kept from the writer).
- `amendments`: amendment items proposed during the session.
- `ended`: map the cause to `FlowSessionEnd`.

Only announce sessions worth a slip: `flowMs >= 60_000` (or `words >= 40`).
Dispatch `new CustomEvent<FlowSession>(FLOW_SESSION_EVENT, { detail })` on
`window`, log it with `logFlow("focus", ...)`, and persist the last 30 sessions
to IndexedDB meta key `"flow-sessions"` using the existing helpers in
`src/utils/idb.ts` (`saveMetaToIdb`, `loadMetaFromIdb`, `toStorable`). IMPORTANT:
never put Qwik store proxies into IDB (DataCloneError fails silently); build
plain objects and use `toStorable`. Add a pure, tested helper in
`flow-session.ts`, e.g. `summarizeSession(...)` and `appendSession(list, s, max)`,
plus `loadFlowSessions()`.

Also add `lastSession(): FlowSession | null` to the `FlowController` interface
so the margin can show the most recent slip after a remount.

## Task 2 — "a way in" when stuck

`gather()` already asks Jev `questions.stuck` when `mode === "stuck"` but never
uses the answer. When the writer is stuck and Jev confirms (noul ≥ 0.6, or when
no client is available, fall back to the local reading only if the struggle
signal is strong), upsert ONE item:

```ts
{ id: `way-in:${key.slice(0, 40)}`, kind: "way-in", anchors: [text],
  title: <short prompt>, body: <one or two sentences>, byline?: string,
  links?: [<id of the best echo item for this passage, if any>], createdAt, relevance }
```

System One returns typed judgements, not prose, so pick the prompt with a
`choice` question from a fixed set of ways in, and fill the body from a
template that uses the dossier (`stack.fields.goal/audience`) and the
passage. Suggested set (tune the wording; keep it short, warm, never bossy):

- "Say it plainly first" — write the sentence as you'd say it to <audience>, then dress it.
- "Start from the thing itself" — one concrete detail you can see.
- "Who is this for?" — <goal / audience line from the dossier>.
- "Pick up an earlier thread" — only offered when an echo matched; link it.
- "Leave a mark and move on" — type TK and write the next paragraph.

Only one way-in at a time; dismissing it must keep it dismissed for that
passage. It should rank first while stuck (priority is already 0.95), and it
should not be offered in any other mode (make `decideSurface` hold it outside
`stuck`, with a reason string). Add policy tests.

## Task 3 — fallback conversation cards follow their passage

On screens where the flow margin is not active (`marginSurface()` returns null),
the comment / persona-note / suggestion popovers are placed once with
`computeMarginCardGeometry` (which now tucks the card under or over the passage
when there is no margin room) and then stay fixed while the manuscript scrolls.
Make them follow their passage on scroll/resize (rAF-throttled, passive
listener on the manuscript scroller, found the same way `flow-surface.tsx`
finds it: `.page-canvas` parent). Only for popovers whose `margin` is null. If
the passage scrolls fully out of the viewport and the card has no unsent
draft and is not pinned, close it; otherwise clamp it on screen. Keep the
existing `margin`-slot path untouched.
