Yes—**subheadings already work, but a proper subtitle is missing.** I checked Twyne’s source and the current Typst documentation.

In Twyne today:

- **Heading 2 / Heading 3** provide nested section headings. Use `/heading` or the Home toolbar.
- Searching `/subtitle` currently selects **Heading 2**. That’s only an alias; it still becomes a section in the outline.
- There’s no dedicated role for a subtitle beneath the title. [Current commands](/home/diogenes/Projects/twyne/src/utils/editor-commands.ts:161)

Typst has a distinct **`title` element**, introduced in 0.14, alongside nested `heading` elements. It doesn’t currently list a built-in `subtitle` element; subtitles are composed through styling functions or templates. We would need to verify Twyne’s bundled compiler supports `title` before adopting it. [Title documentation](https://typst.app/docs/reference/model/title/), [0.14 release notes](https://typst.app/docs/changelog/0.14.0/)

**The most useful expansion would be named editorial styles.** My recommended first set:

- **Title, subtitle, byline, date** — a coordinated opening, with independent typography and spacing.
- **Kicker** — a short label above the title, such as “Field Notes.”
- **Standfirst** — a larger introductory paragraph beneath it.
- **Epigraph with attribution** — for essays and chapter openings.
- **Pull quote** — a display treatment separate from an ordinary block quotation.
- **Scene break** — selectable ornaments, spacing, or a simple rule.
- **Chapter opener** — chapter number, title, optional subtitle, and opening-paragraph treatment.

These roles could support reusable presets—Essay, Literary Journal, Book, Report—while retaining the same manuscript content. Typst’s `set` and `show` rules are well suited to that separation of content and appearance. [Styling documentation](https://typst.app/docs/reference/styling/)

There are also promising Typst extensions:

- **[Marginalia](https://typst.app/universe/package/marginalia/)** — sidenotes, margin figures, side captions, and wider blocks. Particularly interesting for annotated essays. Its documentation notes page-break limitations for wide blocks.
- **[Chic-hdr](https://typst.app/universe/package/chic-hdr/)** — richer running headers and footers, alternating pages, chapter names, and decorative separators.
- **[Outrageous](https://typst.app/universe/package/outrageous/)** — more control over contents-page typography, indentation, spacing, and leaders.
- **[Droplet](https://typst.app/universe/package/droplet/)** — configurable dropped capitals. Twyne already has an illuminated-initial implementation, so this is worth comparing before considering replacement.
- **[Fletcher](https://typst.app/universe/package/fletcher/)** — vector diagrams with arrows, useful for illustrated nonfiction and technical writing.

**I’d start with subtitle, kicker, standfirst, epigraph, and scene break, then add reusable style presets.** They would expand everyday writing and design options without requiring writers to edit Typst.

Implementation-wise, Tiptap supports custom nodes and attributes, so these can be real editable roles. Each needs matching editor styling, Typst rendering, and source round-trip support; currently, unfamiliar Typst expressions become opaque blocks in Write view. Installing a Typst package alone won’t give us the corresponding visual editing experience. [Tiptap extension documentation](https://tiptap.dev/docs/editor/extensions/custom-extensions/extend-existing), [Twyne’s source bridge](/home/diogenes/Projects/twyne/src/utils/typst/document.ts:4)
