The most telling signal: On almost every single day, pageviews = unique users. That means each person appears to only visit one page per session – which is impossible if they're actually using the app.

---

🐛 The two root causes

1. SPA navigation isn't being tracked

PostHog's JavaScript SDK automatically captures pageview events on page load. The problem with single-page apps is that page loads don't happen beyond the initial one – meaning user navigation inside the app isn't tracked at all.

So when a user loads the homepage and then navigates to the editor, PostHog only sees the homepage visit. Every subsequent page they visit is invisible.

The fix: You can opt-in to tracking SPA navigation by setting the defaults config option to the most recent date when initializing PostHog. Recent defaults set capture_pageview: 'history_change', which captures SPA navigation using the browser history API.

For Next.js app router, the recommended approach is to use a PostHogProvider component initialized with updated defaults – see the SPA pageview tracking tutorial (https://posthog.com/tutorials/single-page-app-pageviews) for the exact setup.

2. Users aren't being identified after sign-in

Only 2 users were identified in the past 30 days. This means everyone who signs in and uses the editor is being tracked as an anonymous visitor with a random ID. When they come back the next day, PostHog sees them as a brand new person.

The fix: Call posthog.identify() after a user successfully signs in:

posthog.identify(user.id, {
 email: user.email,
 name: user.name,
})

This should happen in your auth callback / sign-in success handler. See the Next.js identify example (https://posthog.com/questions/next-js-app-directory-client-side-tracking-identify-example) for how to wire this up in the app router.
